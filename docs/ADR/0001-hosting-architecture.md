# 0001. ホスティング構成：Vercel + ローカルエージェント + Riot 公開 API

- ステータス: 採用
- 日付: 2026-11-19

## 背景

もともとは各自の PC で Node サーバーを動かすローカル専用アプリで、League クライアントの lockfile を読んで LCU API（`https://127.0.0.1:<port>`）からフレンドの状態を取得していた。
これを Vercel にデプロイし、複数人がそれぞれ使えるようにしたい。

制約:

- フレンドリストとオンライン状態は LCU API からしか取れない。Riot の公開 Web API にはこれらのエンドポイントがない。
- LCU API はユーザーの PC のループバックアドレスで待ち受けており、クラウドからは届かない。
- ブラウザから直接 LCU を呼ぶこともできない（自己署名証明書、起動ごとに変わるポートとパスワード、CORS）。

## 検討した案

1. **Vercel + ローカルエージェント**：ユーザーの PC で小さなエージェントを動かし、LCU のデータをクラウドへ送る。今の機能をすべて維持できる。
2. **Riot 公開 API のみ**：完全にクラウドだけで動く。ただしフレンド一覧は表示できず、検知できるのは「試合中」だけ（Spectator-V5）。
3. **両方を併用**：エージェントが動いていれば 1、止まっていれば 2 で補う。

## 決定

**案 3（併用）** を採用する。

- Vercel：静的 UI（`public/`）、サーバーレス API（`api/`）、通知判定、Discord 通知。
- エージェント（`agent/`）：LCU をポーリングし、`POST /api/agent/push` で状態を送る。
- Riot 公開 API（`lib/riot.js`）：エージェントが LCU に繋がっていない間だけ、監視リストの Riot ID が試合中かを確認する（[0005](0005-riot-api-fallback.md)）。

## 結果

- 良い点：エージェントを動かせば従来と同じ精度で通知できる。PC を閉じていても試合開始だけは検知できる。
- 悪い点：フル機能にはユーザーの PC で Node.js とエージェントの起動が必要。データ源が 2 つになり、重複通知の防止が必要になる（[0006](0006-notification-detection.md)）。
- 従来の `server/index.js`・`server/store.js` は廃止し、`lcu.js`・`mock.js` は `agent/` に移した。
