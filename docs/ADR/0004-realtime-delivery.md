# 0004. ブラウザへの配信：SSE をやめて 5 秒ごとのポーリングにする

- ステータス: 採用
- 日付: 2026-11-19

## 背景

従来はローカルサーバーが SSE（`/api/events`）で状態とアラートをブラウザへ流していた。
Vercel のサーバーレス関数は実行時間に上限があり、インスタンスも状態を持たないため、長時間つなぎっぱなしの接続や、別インスタンスで起きたイベントの配信には向かない。

## 検討した案

- **SSE / WebSocket を維持**：Pusher や Ably などのリアルタイム配信サービスが別途必要になる。
- **ポーリング**：追加サービス不要。遅延は最大でポーリング間隔ぶん増える。

## 決定

ブラウザが `GET /api/state` を **5 秒ごとに** 取得する（`public/app.js` の `pollState`）。

- 通知ログはサーバーに保存し、ブラウザ側でアラート ID の既読管理をする。新しい ID だけをトースト・音・デスクトップ通知で知らせる。
- 最初の取得分は既読扱いにし、ページを開いた瞬間に過去の通知が一斉に鳴らないようにする。
- テスト通知は保存せず、`/api/test-notify` の応答をそのまま表示する。

## 結果

- 良い点：追加のインフラなしで Vercel だけで完結する。
- 悪い点：通知の遅延がエージェントのポーリング間隔＋最大 5 秒になる。バックグラウンドのタブではブラウザがタイマーを間引くので、さらに遅れることがある。ブラウザを閉じていても確実に受け取るには Discord Webhook を使う。
- 5 秒ごとの取得が Upstash のコマンド数を消費する（1 回 1 コマンド。[0002](0002-data-store.md)）。
