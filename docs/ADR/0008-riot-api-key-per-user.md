# 0008. Riot API キーはユーザーが設定画面で登録する

- ステータス: 採用（[0005](0005-riot-api-fallback.md) の API キーの扱いを置き換える）
- 日付: 2026-11-19

## 背景

[0005](0005-riot-api-fallback.md) では、運営者が Vercel の環境変数 `RIOT_API_KEY` に 1 つだけキーを設定していた。
この方式には次の問題があった。

- キーの登録や更新のたびに、Vercel の管理画面と再デプロイが必要。
- Riot のレート制限（Personal キーで 100 回 / 2 分）を全ユーザーで取り合う。
- 利用者が自分の Personal キーを持っていても使えない。

## 決定

- Riot API キーを **ユーザーごとの設定**（`settings.riotApiKey`、`u:<uid>:cfg` に保存）とし、設定画面から登録・削除できるようにする。
- 環境変数 `RIOT_API_KEY` は使わない。キーを登録していないユーザーでは Riot API のチェックを行わない。
- 保存時の検証：
  - 形式（`RGAPI-` ＋ UUID）を確認する。
  - Riot の `lol/status/v4/platform-data` を 1 回呼び、401 / 403 なら保存しない。429 はキー自体は有効とみなす。
- ブラウザへは値を返さず、`RGAPI-…xxxx`（末尾 4 文字）だけ返す。Discord Webhook と同じ扱い。
- **PUUID のキャッシュキーに API キーのハッシュを含める**（`riot:puuid:<sha256(key) 先頭16桁>:<name#tag>`）。PUUID は API キーごとに暗号化された値なので、別のキーのキャッシュを使うと Spectator が 400 になるため。
- キーを変更したら、そのユーザーの前回の確認結果とエラーを捨て、次の取得ですぐ確認し直す（通知ログと通知時刻は残す）。
- `/api/cron` は全ユーザーを巡回し、キーを登録していないユーザーは何もせずに飛ばす。

## 結果

- 良い点：
  - Vercel 側で Riot API の設定が要らなくなり、運営者に必要な環境変数は Upstash だけになる（Cron を使う場合は `CRON_SECRET` も）。
  - レート制限がユーザーごとに分かれる。
- 悪い点：
  - API キーを Upstash に平文で保存する。Riot API を呼ぶたびにキーが必要なので、ハッシュ化はできない。Upstash の管理者は読めることを README に明記した。
  - 利用者それぞれが Riot Developer Portal でキーを用意する必要がある。
