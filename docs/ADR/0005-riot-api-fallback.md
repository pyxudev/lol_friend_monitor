# 0005. Riot 公開 API による補完：エージェント停止中だけ試合中を検知する

- ステータス: 採用
- 日付: 2026-11-19

## 背景

エージェントは、ユーザーが PC で League クライアントとエージェントを起動している間しか動かない（[0001](0001-hosting-architecture.md)）。それ以外の時間も、監視している相手が試合を始めたことくらいは知りたい。

## 決定

- 監視リストの Riot ID（`名前#タグ`）を Account-V1 で PUUID に変換し、Spectator-V5 で進行中の試合があるかを確認する（`lib/riot.js`）。
- API キーは運営者のものを環境変数 `RIOT_API_KEY` で 1 つ設定する。プラットフォーム（jp1 / kr など）はユーザーごとの設定にする。
- **エージェントが LCU に繋がっている間は実行しない**。エージェントの方が詳しく速いうえ、API の制限も節約できる。このとき Riot 側の前回状態は捨て、再開したときに古い状態と比べて誤通知しないようにする。
- 初めて確認した相手は基準を取るだけにする。前回「試合外」だった相手が「試合中」になったときに通知する。
- 実行のきっかけは 2 つある。
  - ブラウザの `GET /api/state` のついで（1 ユーザーにつき 60 秒に 1 回まで）。手動更新は 15 秒に 1 回まで。
  - `GET /api/cron`（`Authorization: Bearer <CRON_SECRET>`）で全ユーザーを巡回する。
- 1 回で確認するのは最大 20 人。429 が返ったらその回は打ち切り、取れなかった相手は前回の状態を引き継ぐ。
- PUUID は API キーごとに暗号化された値なので、Redis に 7 日間キャッシュする。Spectator が 400 を返したら（キーを変えた場合など）キャッシュを捨てる。

## 結果

- 良い点：PC を閉じていても試合開始を通知できる。
- 制約：
  - ロビー・キュー中・チャンピオン選択は検知できず、間隔も約 1 分と粗い。
  - Vercel Hobby プランの Cron は 1 日 1 回までなので、ブラウザを閉じていても検知するには外部の cron サービス（cron-job.org など）か Pro プランが必要。
  - 開発用 API キーは 24 時間で失効するため、続けて運用するなら Personal / Production キーの申請が必要。
  - LCU のフレンドの PUUID と公開 API の PUUID は一致しないので、照合には Riot ID を使う。タグのない監視対象は確認できない。
