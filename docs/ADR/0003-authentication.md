# 0003. 認証：メール不要のトークン方式（ユーザー用とエージェント用を分ける）

- ステータス: 採用
- 日付: 2026-11-19

## 背景

複数人が使うため、ユーザーごとにデータを分ける必要がある。一方で、個人の小さなツールなので、メール認証や OAuth を入れる手間はかけたくない。
また、エージェントは各自の PC に置かれるため、そこに置く認証情報は漏れたときの影響を小さくしたい。

## 決定

アカウント作成時（`POST /api/account`）に 2 種類のランダムなトークンを発行する。

| トークン | 接頭辞 | 使う場所 | できること |
|---|---|---|---|
| ユーザートークン | `lfwu_` | ブラウザ（`localStorage`） | すべての操作 |
| エージェントトークン | `lfwa_` | エージェント（`~/.lol-friend-watcher/agent.json`） | フレンド状態の送信（`/api/agent/push`）のみ |

- どちらも `Authorization: Bearer` で送る。サーバーは SHA-256 ハッシュをキーにして uid と種類を引く（`lib/users.js` の `authenticate`）。
- 種類が違うトークンは 403 にする（エージェントトークンでは設定を読めない、など）。
- ユーザートークンは平文で保存しない。作成時に返すだけで、別端末で使うときは設定画面からコピーする。
- エージェントトークンは設定画面にコマンドとして表示するため、`cfg` に平文でも持つ。漏れた場合は `POST /api/agent/token` で再発行し、古いものを無効にできる。
- アカウント作成は IP ごとに 1 時間 10 回までに制限する。
- `DELETE /api/account` で、トークンを含むすべてのキーを削除する。

## 結果

- 良い点：メールやパスワードを扱わず、Riot の認証情報にも触れない。エージェントトークンが漏れても、できるのは状態の送信だけ。
- 悪い点：ユーザートークンを失くすとアカウントを復旧できない（ログアウト時に確認ダイアログで注意を出している）。
- 将来本格的なユーザー管理が必要になったら、OAuth（Discord ログインなど）への置き換えを検討する。
